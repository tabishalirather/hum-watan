Benefits of This Approach

  • Single codebase with no duplicated types between frontend and backend.
  • Feature isolation through vertical slices makes it easy to grow the project.
  • Server Components and Server Actions reduce client-side complexity and API boilerplate.
  • Drizzle and PostgreSQL provide strong type safety and simple migrations.
  • The architecture scales well from an MVP to a much larger application without forcing an early move to microservices.

The only architectural change I'd make to a "pure" vertical slice is to distinguish commands (mutations) from queries (reads). Rather than naming everything "actions," I prefer a lightweight CQRS-inspired structure:

features/
└── appointments/
    ├── commands/
    │   ├── create-booking.ts
    │   ├── cancel-booking.ts
    │   └── update-availability.ts
    ├── queries/
    │   ├── get-bookings.ts
    │   ├── get-calendar.ts
    │   └── get-upcoming.ts
    ├── repository/
    ├── service/
    ├── components/
    ├── validators/
    └── types/

This makes it immediately obvious which files change state and which only read data, and it scales exceptionally well as the application grows.
